# Convolutional Neural Networks

## 1. Why Convolutions Suit Images
A convolutional neural network, or CNN, is a neural architecture designed to exploit the spatial structure of data such as images. A fully connected layer treats every input pixel as an independent feature and connects it to every output unit. For a large image, this creates an enormous number of parameters and ignores the fact that nearby pixels often form meaningful patterns. CNNs instead use local receptive fields and shared filters, allowing the same feature detector to operate at many image locations.

A convolutional filter is a small matrix of learned weights that slides across an input. At each position, it computes a weighted sum of the local image patch, usually adds a bias, and produces one value in a feature map. Different filters learn to respond to different patterns, such as edges, corners, textures, or more complex structures. The filter weights are shared across positions, which reduces parameter count and gives the operation a useful translation-equivariant property: shifting an input pattern generally shifts its activation pattern.

Convolution is often described as detecting features, but the filters are not manually assigned to detect particular objects. They are learned through optimization using the training objective. Early layers may learn simple local patterns, while deeper layers combine those responses into larger structures. This hierarchy is an empirical tendency, not a strict rule that every network follows.

The local assumption is powerful but not always sufficient. A standard convolution has limited context unless many layers are stacked, and it does not automatically understand long-range relationships between distant image regions. CNNs therefore use pooling, strides, dilation, larger kernels, or global modules to expand context. Their inductive bias is particularly helpful when spatial locality and repeated patterns are meaningful, as in natural images, medical microscopy, and many industrial inspection tasks.

## 2. Convolution Operation and Feature Maps
For a two-dimensional image, a convolutional layer applies a kernel across height and width. At each valid position, corresponding input and kernel values are multiplied and summed. In deep-learning libraries, the operation commonly called convolution is technically cross-correlation, because the kernel is not flipped before sliding. This distinction rarely affects learning because the kernel values are learned, but it matters when implementing the mathematical operation by hand.

An input tensor generally has height, width, and channels. A filter spans the spatial dimensions of its receptive field and all input channels, producing one output channel. A layer with many filters produces many feature maps. For example, a layer with 32 filters creates 32 output channels, each responding to a learned pattern. The number of parameters depends on kernel height, kernel width, input channels, and output channels, plus optional biases. It does not depend directly on image height and width because the same filters are reused spatially.

Stride determines how far the filter moves at each step. A stride of one evaluates adjacent positions; a stride of two skips positions and typically reduces spatial resolution. Padding adds values, often zeros, around the input border. “Valid” convolution uses no padding and shrinks spatial dimensions, whereas “same” padding is commonly chosen to preserve dimensions when stride is one. Output dimensions depend jointly on input size, kernel size, padding, and stride, so careless assumptions can cause shape mismatches in multi-branch networks.

The word convolution can also refer to grouped or depthwise operations. Grouped convolution divides channels into groups that are processed separately, reducing computation. Depthwise convolution applies a spatial filter independently to each input channel, often followed by a pointwise one-by-one convolution to mix channels. These designs are central to efficient architectures for mobile and edge devices.

## 3. Activations, Pooling, and Downsampling
A convolution is usually followed by a nonlinear activation. Without nonlinearities, a stack of convolutional and linear operations would still represent a linear transformation and would lack the expressive power expected of a deep network. ReLU replaces negative values with zero and preserves positive values. It is computationally simple and often supports effective gradient flow, although units that remain negative can become inactive. Variants such as Leaky ReLU preserve a small negative slope.

Pooling reduces spatial dimensions by summarizing local neighborhoods. Max pooling returns the largest value in a region, while average pooling returns the mean. Pooling can reduce computation and make representations less sensitive to small translations, but it discards precise spatial information. This is acceptable for image classification more often than for tasks requiring exact localization, such as segmentation or object detection. Modern networks also downsample through strided convolutions, which learn the reduction rather than using a fixed pooling rule.

Downsampling creates a trade-off between receptive field and detail. A feature at a deep, low-resolution stage can represent broad context, but small objects or fine boundaries may disappear. Segmentation systems often use encoder-decoder designs: the encoder progressively reduces resolution and extracts semantic features, while the decoder restores spatial resolution. Skip connections transfer high-resolution features from encoder stages to corresponding decoder stages, helping recover edges and small structures.

Global average pooling averages each feature map over its spatial positions and produces one value per channel. It can replace large fully connected classifier layers and reduce parameter count. A common pitfall is to downsample aggressively without checking the smallest relevant object. In microscopy, a nucleus may occupy only a small number of pixels; repeated stride-two operations can erase it. Resolution and stride should therefore be selected with the target scale and evaluation requirements in mind.

## 4. Receptive Fields and Hierarchical Features
The receptive field of a unit is the region of the original input that can influence its activation. A small kernel in an early layer sees a small local patch. As layers are stacked, later units combine information from multiple earlier positions, so their effective receptive fields cover larger image regions. Strided downsampling expands the input area represented by each later feature location. Dilation expands spacing between kernel samples without necessarily increasing parameter count or reducing resolution.

The theoretical receptive field describes every input position that can affect a unit. The effective receptive field describes how strongly those positions influence it in practice. Influence is often concentrated near the center rather than distributed uniformly across the theoretical region. This matters when deciding whether a model has enough context to distinguish visually similar structures. For example, classifying an isolated cell may require both nuclear morphology and nearby cytoplasmic context, while detecting a large tissue pattern requires a broader field.

Hierarchical feature learning is one reason CNNs work well. Early stages often respond to local intensity changes and edges. Intermediate stages combine those responses into textures or repeated motifs. Deeper stages can represent object parts or class-specific patterns. These descriptions are useful intuitions, but learned channels are not guaranteed to correspond to human-interpretable concepts. Feature visualization and attribution methods can help investigate what a network uses, although such explanations should not be treated as definitive proof of causal reasoning.

A frequent design error is to equate a larger receptive field with better performance. Excessive context can introduce irrelevant background, while aggressive downsampling can destroy small details. Dilated convolutions can expand context but may create gridding artifacts if dilation rates are chosen poorly. Multi-scale designs combine features at several resolutions so that local detail and broad context are both available. The appropriate balance depends on object size, image resolution, dataset diversity, and the task's need for localization.

## 5. CNN Architectures and Skip Connections
Classic CNNs established progressively deeper feature hierarchies. LeNet demonstrated convolutional processing for handwritten digits. AlexNet popularized deep convolutional networks on large-scale image classification and used ReLU and GPU training. VGG used repeated small convolutions to build depth with a simple design, while Inception modules processed features with multiple kernel sizes and branches. These architectures illustrate different ways to balance depth, width, receptive field, and computational cost.

As networks became deeper, optimization became more difficult. Residual networks introduced skip connections that add a block's input to its transformed output. The identity path allows information and gradients to pass through a block without requiring every layer to learn a complete transformation. A residual block can therefore learn a correction to its input. When dimensions differ, a projection such as a one-by-one convolution can align shapes before addition.

Dense connectivity takes a different approach by concatenating features from earlier layers, encouraging feature reuse but increasing memory demands. Encoder-decoder architectures such as U-Net are widely used for segmentation. U-Net combines a contracting path that captures context with an expanding path that restores resolution. Skip connections between matching scales preserve localization cues. Feature pyramid networks similarly combine information across scales and are common in object detection.

Architecture choice should account for the task rather than popularity. Classification can often use global pooling and a compact head. Detection requires object locations and scales, while semantic segmentation predicts a class for every pixel. Instance segmentation must additionally distinguish separate objects of the same class. A CNN backbone may support all these tasks, but the prediction heads and training losses differ. Reusing a classifier without redesigning its output head does not automatically create a valid detector or segmenter.

## 6. Training CNNs and Data Considerations
CNN training follows the same general optimization process as other neural networks: a forward pass produces predictions, a loss measures error, backpropagation computes gradients, and an optimizer updates parameters. The output layer and loss must match the task. Multiclass classification commonly uses softmax with cross-entropy, binary classification uses a sigmoid-compatible binary cross-entropy objective, and segmentation may combine pixelwise cross-entropy with Dice or overlap-based losses.

Image preprocessing is part of the model definition. Resizing, cropping, color conversion, normalization, and channel ordering must be consistent between training and inference. Normalization may use per-channel means and standard deviations estimated from training data or a pretrained model's expected values. If training images are RGB but inference images are supplied in BGR order, performance can collapse despite apparently correct tensor shapes. Medical images add further concerns: stain variation, scanner differences, magnification, focus, and slide-level correlations can create substantial distribution shifts.

Augmentation can improve robustness by applying transformations that preserve the label, such as flips, rotations, crops, brightness changes, or mild color variation. However, transformations must respect domain semantics. A rotation may be harmless for a cell image but a vertical flip may be invalid for a document or directional radiology task. Excessive augmentation can produce unrealistic examples and harm learning.

Data splitting is especially important when images are derived from the same patient, slide, video, or acquisition session. Randomly splitting individual crops can leak highly similar content across training and test sets, inflating apparent performance. Group-level splitting should keep related samples together. Class imbalance can also make accuracy misleading; class-weighted losses, balanced sampling, or targeted collection may be needed. The model should ultimately be tested on data that reflects the intended deployment environment.

## 7. CNN Limitations, Interpretation, and Deployment
CNNs have strong spatial inductive biases, but those biases can become limitations when relationships across distant regions are essential. A convolutional stack can represent long-range dependencies, yet doing so may require many layers or large receptive fields. Attention modules and hybrid CNN-transformer systems address this by allowing features at different positions to interact more directly. CNNs may also be sensitive to texture, acquisition artifacts, or shortcuts correlated with labels rather than the underlying object.

Interpretability tools include activation maps, saliency maps, Grad-CAM, occlusion tests, and feature visualizations. Grad-CAM uses gradients flowing into a convolutional feature map to estimate which spatial regions contributed to a target class score. Such maps can reveal whether a classifier focuses on plausible regions, but they do not prove that the model's reasoning is correct. A heatmap may be coarse, unstable, or influenced by correlated background features. In high-stakes settings, visual explanations should complement rigorous external validation and expert review.

Deployment introduces constraints beyond predictive accuracy. Convolutional models can be compute-intensive at high resolution, and memory use depends on intermediate feature maps as well as parameter count. Quantization, pruning, channel reduction, and efficient operators can reduce latency or memory, but may change accuracy. Edge devices may have different supported operators and numerical precision from training machines, so the exported model must be tested on the actual target hardware.

A practical evaluation reports more than a single score. Measure throughput, per-image latency, peak memory, input resolution, batch size, and performance across relevant subgroups. For detection and segmentation, assess localization and boundary quality, not just classification accuracy. Monitor failures caused by blur, unusual staining, artifacts, and out-of-distribution images. A CNN is useful only when its full data, training, validation, and deployment pipeline behaves reliably.
