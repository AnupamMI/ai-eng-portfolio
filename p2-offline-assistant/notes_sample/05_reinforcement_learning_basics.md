# Reinforcement Learning Basics

## 1. The Reinforcement Learning Setting
Reinforcement learning, or RL, studies how an agent learns to make decisions by interacting with an environment. At each time step, the agent observes a state, chooses an action, receives a reward, and transitions to a new state. The objective is usually to maximize cumulative reward over time rather than to predict a fixed label for each independent example. This makes RL different from ordinary supervised learning, where the desired output is supplied for every training input.

The agent's behavior is described by a policy. A deterministic policy maps each state to an action, while a stochastic policy assigns probabilities to possible actions. The environment determines the consequences of actions, including next states and rewards. The agent may not know these dynamics in advance and must learn from experience. A central challenge is that an action can have delayed consequences: a choice that gives little immediate reward may lead to a better future state.

RL is useful for problems involving sequential decisions, such as game playing, robotics, resource allocation, and adaptive control. However, it is not automatically the right tool whenever a task contains a sequence. If reliable labeled examples are available and decisions do not influence future data, supervised learning may be simpler and more sample-efficient. RL can require many interactions, and real-world exploration may be costly or unsafe.

The reward function is a critical design choice. An agent optimizes the reward it receives, not the designer's unstated intention. If reward omits important constraints, the agent may exploit loopholes or learn undesirable behavior. For example, a robot rewarded only for speed may collide with obstacles. Practical RL therefore requires careful reward design, constraints, simulation validation, and monitoring of behavior beyond the scalar reward total.

## 2. Markov Decision Processes
A Markov decision process, or MDP, formalizes many RL problems. It is defined by a set of states, a set of actions, transition probabilities, a reward function, and a discount factor. The Markov property states that the next state depends on the current state and action, not on the full history, once the current state is known. In other words, the state must contain the information needed to predict future transitions and rewards.

The transition model gives the probability of reaching a next state after taking an action in the current state. The reward function specifies the expected immediate reward associated with a transition or state-action pair. The discount factor, usually written gamma, lies between zero and one in continuing discounted tasks. It determines how strongly future rewards are valued relative to immediate rewards. A value close to one emphasizes long-term consequences, while a smaller value emphasizes near-term reward.

An episode is a finite interaction that ends at a terminal state, such as a completed game or a robot reaching a goal. Continuing tasks may not have a natural terminal state and are often handled using discounting or average-reward objectives. The return is the cumulative discounted reward from a time step onward. In words, it is the immediate reward plus future rewards, each multiplied by a discount factor raised to its distance in time.

The Markov assumption is a modeling convenience, not a guarantee about the real world. If an observation omits relevant history, the process may be partially observable. A robot camera image may not reveal velocity, for example, so the current image alone may not determine the next-state distribution. The agent may need a history window, a recurrent state, or a belief distribution over hidden states.

## 3. Value Functions and the Bellman Principle
A value function estimates how much cumulative reward an agent can expect from a state or state-action pair. The state-value function for a policy is the expected return when starting in a state and following that policy. The action-value function, commonly called Q, is the expected return after taking a specified action in a state and then following the policy. These functions help compare choices based on both immediate and future consequences.

The Bellman expectation equation expresses a value recursively. A state's value equals the expected immediate reward plus the discounted value of the next state under the policy. This works because the return can be separated into the first reward and the remaining future return. The Bellman optimality equation replaces the policy's action choice with the maximum over available actions, describing the best achievable value under the model.

The principle of optimality says that an optimal policy has the property that, after any first action, its remaining decisions must also be optimal for the resulting state. This recursive structure enables dynamic programming methods when the transition model is known and the state space is manageable. In model-free RL, algorithms estimate value functions from sampled transitions rather than requiring a complete environment model.

Value estimates can be inaccurate early in training. If an algorithm repeatedly bootstraps from its own estimates, errors may propagate. Function approximation introduces additional challenges because changing parameters to improve one state's estimate can affect many other states. A high value estimate does not mean the agent will certainly obtain that return; it is an expectation under the modeled policy and environment. Evaluation should therefore include repeated episodes and variation in outcomes, not only a value-function snapshot.

## 4. Exploration and Exploitation
An RL agent must balance exploitation and exploration. Exploitation chooses actions that currently appear to have high value. Exploration tries actions whose outcomes are uncertain in order to discover potentially better behavior. Pure exploitation can trap an agent in a mediocre strategy because it never gathers evidence about alternatives. Pure exploration wastes reward by repeatedly choosing uncertain actions even when a strong policy has already been learned.

A simple strategy for discrete actions is epsilon-greedy selection. With probability epsilon, the agent chooses a random action; otherwise, it chooses the action with the highest current Q estimate. Epsilon may be reduced during training so that exploration is more frequent early and less frequent later. However, decaying epsilon too quickly can prevent discovery, while keeping it high can make evaluation appear poor because the agent continues acting randomly.

Other methods include softmax action selection, upper-confidence-bound strategies, and Thompson-style sampling. Softmax assigns higher probabilities to actions with higher estimated values, with a temperature controlling randomness. Uncertainty-aware methods explicitly encourage actions whose value estimates are uncertain. In deep RL, entropy bonuses can encourage stochastic policies and prevent premature collapse to one action.

Exploration is not merely a training hyperparameter in real environments. It can cause physical damage, financial loss, or unsafe behavior. Robotics systems often explore in simulation or under constrained conditions before real-world deployment. Offline RL learns from previously collected data and avoids direct exploratory interaction, but it faces a different problem: the learned policy may choose actions poorly represented in the dataset. Safe exploration and distribution coverage are therefore central design considerations.

## 5. Q-Learning and Temporal-Difference Updates
Q-learning is a model-free, off-policy algorithm that learns an action-value function for an optimal policy. It updates an estimate using a sampled transition consisting of the current state, chosen action, reward, and next state. The target is the observed reward plus the discounted maximum Q-value over possible actions in the next state. The update moves the current estimate toward this target by a learning-rate fraction of the temporal-difference error.

The temporal-difference error is the difference between the target and the current estimate. It measures how surprising the transition is relative to the model's prediction. Q-learning is off-policy because it can learn the greedy optimal action values while behavior during training follows an exploratory policy such as epsilon-greedy. The next-state maximum is used in the target even if the behavior policy might choose a different action.

A tabular Q-learning agent stores one value for each state-action pair. This is feasible for small discrete problems, such as a small grid world, but impossible for large or continuous state spaces. Deep Q-networks approximate Q-values using a neural network. They commonly use experience replay, which samples past transitions to reduce correlation, and a target network, which stabilizes the target calculation by updating a separate set of parameters less frequently.

Q-learning has important pitfalls. The maximum over noisy value estimates can cause overestimation. Double Q-learning and Double DQN reduce this bias by separating action selection from action evaluation. Function approximation can also destabilize learning, especially when combined with off-policy updates and bootstrapping. Reward scaling, terminal-state handling, replay sampling, and target-network update frequency all matter. A high training reward over a few episodes is not enough to establish robust performance.

## 6. Policy Gradients and Actor-Critic Methods
Policy-gradient methods optimize a parameterized policy directly rather than first learning only action values. A stochastic policy assigns probabilities to actions, and the objective is expected cumulative reward. The policy-gradient theorem expresses the gradient of this objective in terms of the gradient of the log probability of selected actions multiplied by an estimate of their return or advantage. Intuitively, actions associated with better-than-expected outcomes become more likely, while worse outcomes become less likely.

A direct policy-gradient method such as REINFORCE can use complete episode returns as its learning signal. This is conceptually simple but often has high variance, because outcomes depend on many random events. A baseline can reduce variance without changing the expected gradient when it does not depend on the sampled action. A state-value estimate is commonly used as the baseline, producing an advantage estimate that measures how much better an action performed than expected from that state.

Actor-critic methods combine a policy, called the actor, with a value estimator, called the critic. The actor chooses actions, while the critic estimates values or advantages to guide policy updates. This can provide lower-variance learning signals than using raw returns, though it introduces approximation bias and additional training dynamics. Algorithms such as A2C, PPO, and SAC use actor-critic ideas in different ways. PPO constrains policy updates through a clipped objective, while SAC encourages entropy in continuous-control settings.

Policy-gradient methods naturally handle stochastic policies and continuous action spaces, where enumerating all actions is impossible. They can nevertheless be sensitive to learning rates, reward scales, advantage normalization, and the quality of critic estimates. A policy that improves average reward may still have rare catastrophic failures. Evaluation should inspect distributions, constraint violations, and robustness across seeds and environment variations.

## 7. RL Evaluation and Practical Pitfalls
RL evaluation is difficult because outcomes are stochastic and training data is generated by the current policy. Report mean return across multiple independent evaluation episodes, along with variability such as standard deviation or confidence intervals. Also measure task completion, constraint violations, episode length, energy use, safety events, or other domain-specific outcomes. A high reward can conceal poor behavior if the reward function omits an important requirement.

Training curves should be averaged across multiple random seeds when possible. Deep RL results can vary substantially with initialization, environment randomness, and implementation details. Comparing algorithms using a single seed or a small number of episodes can produce misleading rankings. Evaluation should use a separate environment configuration or held-out scenarios where possible, and exploration should usually be disabled or controlled during final policy evaluation.

Simulation-to-reality transfer is a major concern in robotics and control. A policy can exploit simulator artifacts that do not exist in the physical world. Domain randomization varies physical parameters, sensor noise, and environmental conditions during training to improve robustness. Even then, real-world testing should be staged and constrained. Offline RL has its own distribution-shift risk: the learned policy may select actions outside the support of the logged data.

Reproducibility requires documenting the environment version, reward definition, observation and action spaces, algorithm, network architecture, hyperparameters, training steps, seeds, and evaluation protocol. RL should be selected when sequential interaction and delayed consequences genuinely matter. If the problem can be solved reliably with supervised learning, planning, or optimization, those approaches may be easier to validate. The strongest RL system is not simply the one with the largest reward curve; it is the one whose behavior remains useful and safe under realistic conditions.
