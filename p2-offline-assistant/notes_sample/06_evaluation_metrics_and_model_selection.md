# Evaluation Metrics and Model Selection

## 1. Why Evaluation Must Match the Task
Model evaluation estimates how well a trained system will perform on data it has not used for fitting. The metric should reflect the actual task and the relative cost of different errors. Accuracy is intuitive for balanced classification, but it can be misleading when classes are imbalanced or when false positives and false negatives have different consequences. A screening model, for example, may prioritize sensitivity because missing a positive case is costly, while a fraud-review system may need to control false alarms because human investigation is expensive.

A confusion matrix summarizes classification outcomes. For binary classification, true positives are positive examples predicted positive; false positives are negative examples predicted positive; true negatives are negative examples predicted negative; and false negatives are positive examples predicted negative. These four counts form the basis of precision, recall, specificity, F1, and many other metrics. Always state which class is treated as positive, because reversing the positive label changes the interpretation.

Evaluation also depends on the unit of analysis. In medical imaging, a system may predict at the cell, image, slide, or patient level. Strong cell-level performance does not automatically imply strong patient-level screening performance. Multiple predictions may need aggregation, and a single patient may contribute many correlated images. The reported unit should match the intended decision and avoid treating correlated crops as independent observations.

A good evaluation protocol separates training, validation, and test data. Training data fits model parameters, validation data supports hyperparameter and threshold selection, and the test set is reserved for final assessment. Repeatedly adjusting a model based on test results turns the test set into part of the development process and creates optimistic bias. Evaluation quality depends as much on split design and data independence as on the choice of metric.

## 2. Precision, Recall, and Specificity
Precision is the proportion of predicted positive cases that are truly positive. It is calculated as true positives divided by the sum of true positives and false positives. High precision means that positive predictions are usually correct, so false alarms are relatively uncommon among flagged cases. Precision is especially important when follow-up actions are costly or when users lose trust after frequent false alerts.

Recall, also called sensitivity or true-positive rate, is the proportion of actual positive cases that the model correctly identifies. It is calculated as true positives divided by the sum of true positives and false negatives. High recall means few actual positives are missed. In disease screening, missing a positive case may be more serious than sending some negative cases for additional review, so recall may receive high priority.

Specificity is the proportion of actual negative cases correctly identified. It is true negatives divided by the sum of true negatives and false positives. The false-positive rate is one minus specificity. Precision and recall respond differently to class prevalence: even if sensitivity and specificity remain stable, precision can fall when the positive class becomes rare. This is why a model evaluated on an artificially balanced dataset may have a different positive predictive value in deployment.

No single metric captures every operational cost. A threshold can be selected to achieve a target sensitivity, then the corresponding specificity and precision can be reported. In high-stakes settings, confidence intervals and subgroup performance should accompany point estimates. A model should not be described as “accurate” without clarifying which metric, positive class, threshold, and evaluation population support that claim.

## 3. F1 Score and Precision-Recall Analysis
The F1 score is the harmonic mean of precision and recall. It is calculated as two times precision times recall divided by precision plus recall, provided the denominator is nonzero. The harmonic mean penalizes a low value in either component more strongly than the arithmetic mean. A model with high precision but very low recall therefore receives a low F1 score, as does a model with high recall but poor precision.

F1 is useful when both false positives and false negatives matter and a single summary is desired. However, it ignores true negatives, so it may not reflect performance on tasks where correctly rejecting negative cases is important. It also depends on a selected classification threshold. Two models can have similar F1 values but very different precision-recall trade-offs, and a small threshold change can alter F1 substantially.

Macro-F1 computes F1 separately for each class and averages the class scores equally. It gives minority classes the same weight as majority classes, making it useful when every class matters. Micro-F1 aggregates counts across classes before computing the score, so frequent classes have greater influence. Weighted-F1 averages class-level F1 values weighted by class support. These averaging methods answer different questions and should be named explicitly.

For multiclass classification, one-versus-rest precision-recall curves can show the trade-off for each class. In object detection, matching predictions to ground-truth objects introduces additional choices, such as intersection-over-union thresholds and confidence thresholds. In segmentation, overlap measures such as Dice and intersection-over-union are common. A frequent mistake is comparing F1 values produced with different averaging rules, class definitions, or thresholds as if they were directly equivalent.

## 4. ROC Curves and ROC-AUC
A receiver operating characteristic curve plots the true-positive rate against the false-positive rate as the decision threshold varies. Each threshold produces a different pair of values. A model that ranks positive examples above negative examples tends to achieve a curve closer to the upper-left corner, where sensitivity is high and false-positive rate is low. The ROC curve therefore evaluates ranking behavior across thresholds rather than performance at one fixed threshold.

The area under the ROC curve, or ROC-AUC, can be interpreted as the probability that a randomly selected positive example receives a higher score than a randomly selected negative example, with ties handled appropriately. A value near 0.5 indicates ranking no better than random under the usual assumptions, while a value of 1 indicates perfect ranking. ROC-AUC is threshold-independent, but it does not identify an operational threshold or guarantee good calibration.

ROC-AUC can look deceptively strong when the negative class is extremely large. A small false-positive rate may still correspond to a large absolute number of false alarms. In highly imbalanced tasks, precision-recall curves can provide a more informative view of positive prediction quality. The baseline precision of a random ranking in a precision-recall curve is related to positive prevalence, so comparisons should consider the dataset's class distribution.

AUC is also sensitive to how examples are sampled and grouped. If the test set contains near-duplicate images or examples from the same patient in both training and test partitions, the estimate may be inflated. Report the evaluation population, confidence intervals, and relevant operating points. For deployment, pair AUC with threshold-specific sensitivity, specificity, precision, workload, and calibration rather than treating it as a complete description.

## 5. Thresholds, Calibration, and Decision Costs
Many classifiers produce scores or probabilities, then apply a threshold to decide which class to predict. A threshold of 0.5 is conventional for a calibrated binary probability under equal error costs, but it is not universally optimal. Lowering the threshold usually increases recall and false positives, while raising it usually increases precision and false negatives. The appropriate threshold depends on prevalence, capacity for follow-up, and the relative cost of each error.

Calibration describes whether predicted probabilities correspond to observed frequencies. Among examples assigned a probability near 0.8, a well-calibrated model should be correct roughly 80 percent of the time over a sufficiently large representative group. A model can rank examples well and have high AUC while being poorly calibrated. Reliability diagrams compare predicted confidence with observed accuracy across bins, and metrics such as Brier score assess probabilistic error.

Threshold selection should use validation data, not the final test set. A decision rule might maximize F1, meet a minimum sensitivity requirement, or minimize expected cost under a specified cost matrix. These objectives can yield different thresholds. If prevalence changes after deployment, precision and calibration may shift even when ranking performance remains similar. Monitoring and recalibration may be needed, but recalibration cannot fix a fundamental change in the relationship between features and outcomes.

A common mistake is to choose a threshold that maximizes a metric on a small validation set and report the resulting score as if it were unbiased. Threshold tuning is model selection and should be included in the development process. The final test set should evaluate the frozen threshold and pipeline. In clinical or regulated contexts, the operating point should be justified by workflow and risk analysis, not selected solely because it produces the largest numerical score.

## 6. Cross-Validation and Reliable Data Splits
Cross-validation estimates model performance by repeatedly dividing available data into training and validation folds. In k-fold cross-validation, the data is partitioned into k roughly equal folds. The model is trained k times, each time using one fold for validation and the remaining folds for training. The scores are summarized across folds, providing a view of performance variability and reducing dependence on one arbitrary split.

Stratified k-fold cross-validation attempts to preserve class proportions in each fold, which is useful for imbalanced classification. Grouped cross-validation keeps related observations together, such as all images from one patient or all frames from one video. Time-series data generally requires chronological splits because random shuffling can allow future information to influence predictions about the past. The split strategy must reflect how the model will encounter new data.

Cross-validation does not automatically eliminate leakage. Preprocessing steps that learn from data, such as feature scaling, imputation, feature selection, or dimensionality reduction, must be fitted within each training fold and then applied to that fold's validation data. Performing these steps once on the full dataset before cross-validation allows information from validation folds to influence training. Hyperparameter tuning can also overfit cross-validation results if too many configurations are tested without a final independent assessment.

Nested cross-validation separates hyperparameter selection from performance estimation. An inner loop selects settings using training folds, while an outer loop evaluates the selected procedure on held-out folds. It is computationally expensive but useful when data is limited and a separate test set is unavailable. When a final untouched test set exists, cross-validation can be used for model development and stability analysis, followed by one final test evaluation.

## 7. Model Selection, Uncertainty, and Reporting
Model selection chooses among candidate architectures, preprocessing pipelines, hyperparameters, thresholds, and training procedures. The best candidate is not necessarily the one with the highest single validation score. Consider confidence intervals, variability across seeds or folds, computational cost, latency, memory, interpretability, calibration, and robustness to domain shifts. A tiny metric gain may not justify a substantially more complex or expensive system.

Fair comparisons require identical data partitions and clearly defined evaluation rules. If one model receives higher-resolution inputs, stronger augmentation, or more training compute, those differences should be acknowledged. For stochastic training, repeat promising experiments with multiple seeds. For paired model comparisons on the same test examples, paired statistical methods can be more sensitive than treating scores as independent, although assumptions and sample sizes must be checked.

Uncertainty estimates are essential when datasets are small. Bootstrap resampling can estimate confidence intervals by repeatedly sampling evaluation units with replacement. The resampling unit should match the independent unit: if multiple images come from one patient, resample patients rather than individual images. Otherwise, uncertainty may be underestimated because correlated observations are treated as independent. For rare classes, report the number of positive examples because a few errors can change recall dramatically.

A complete report states the dataset source, inclusion criteria, split strategy, grouping unit, class distribution, preprocessing, model-selection procedure, metric definitions, thresholds, and confidence intervals. Include per-class results and a confusion matrix where useful. In deployment-oriented work, also report latency, throughput, memory, and failure analysis. The objective is not to produce the largest possible score but to provide credible evidence that the selected model will perform acceptably under the conditions in which it will be used.
